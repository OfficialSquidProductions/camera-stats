# Local RAW desktop development

This work extends the local desktop workflow; it is not in the published reporting alpha. Sources and report schemas are preserved. No vendor SDK, runtime, test footage or decoded sample image is included in Git or release assets. Browser downloads are disabled for this development run; validation uses authorized samples already on disk.

## Implemented workflow

Native Mac and Compose desktop screens can configure local decoder executables, register an isolated working-copy folder, inspect metadata, decode an exact source-frame index, review a short silent sequence, confirm manual scene/take labels, link a report entry and prepare verified copies. RAW review batches contain at most eight frames. Reverse review ends at the current frame. Native RAW indices/timebases are explicitly clip-relative; they are not packet presentation timestamps. RED's floating-point playback rate is normalized to a nominal rational with the original retained; BRAW reports an exact rational representation of the SDK's float32 rate.

Use **REDline… / Choose REDline** for the separately installed official REDline executable. Use **BRAW… / BRAW helper** for an adapter built locally against an authorized SDK using [native/braw](../native/braw/README.md). Register the source folder again after changing tools. Neither selection downloads or installs vendor software. Source-tree builds also accept `SHOT_REPORTER_REDLINE` and `SHOT_REPORTER_BRAW_HELPER`; these are local tool paths, not update-feed trust overrides. The Mac chooser retains its selected executable path in the existing app preferences; Compose tool selection lasts for the current workspace.

RED packages are complete `.RDC` directories with one recognized, contiguous `_001.R3D`-based span identity. Every regular file below the directory is retained, including unknown sidecars and nested auxiliary files. The outer copied directory receives the naming preset and keeps `.RDC`; internal span names are unchanged. A single isolated BRAW folder is copied as an outer named package, preserving the clip, sidecar and every other listed file. Multiple/nested/overlapping RAW identities, links and special files are refused. Multicard BRAW is refused until explicit member enumeration and real media validation exist. Orphan R3D files and mixed BRAW folders remain registered but cannot be reviewed/copied through an incomplete group.

The inventory lists every member, byte count and SHA-256 before approval. Review it for unrelated/private files, especially for BRAW's conservative whole-folder scope. Package approval and approved-frame evidence bind to the complete inventory fingerprint. Re-enumeration plus all member hashes detect changed, added or removed files before/after decode and before copy verification. Naming preflight rejects missing tokens, invalid internal portable filenames, case/NFC path collisions and excessive Windows paths; it never rewrites internal RAW names to repair them.

**Missing trailing RED spans cannot be detected automatically.** The verified test showed that a first-span-only copy opens as a shorter logical clip with the same UUID. REDline's reported file-segment count also reflects only available spans. The app therefore requires a separate user confirmation against the complete-card copy or source manifest. That confirmation is recorded as user evidence, not automatic card-completeness certification. Registration and successful playback never authorize erasing/reformatting a camera card.

Copy jobs freeze names, report revision/fingerprint, manual frame evidence, native metadata and all source member identities. Each file is copied to a fresh stage, hashed, flushed and published without replacement through a hard link. Metadata and approved-frame re-decode run after all package members are published. Only RED's location field `File Path` is excluded from relocation comparison; native UUID, timing and other metadata remain compared. No embedded metadata or source filename is rewritten. Interrupted stages and journals are retained for resume. Undo checks the whole batch, then retains the same relative package structure under `.undone/<job-id>/`; it does not delete originals or recovery bytes. APFS was exercised; NTFS/native Windows RAW acceptance is pending. Hard-link publication intentionally refuses unsupported destinations; exFAT/network storage is not certified.

Media database schema 2 adds package records without changing `.camreport` schema 1 or the report database. A consistent `media-before-v2-<id>.sqlite3` backup is flushed before a v1 database is upgraded. Older v1-only workers reject the newer database and must use the saved backup for a reviewed rollback; they must not overwrite v2 journals. Unknown records survive migration. Report saves remain separate from media registration/copy journals.

## Actual validation and limits

On Apple silicon macOS, the installed REDline 65.0.20 / internal SDK 9.1.1 decoded official SDK Broadcast sample footage: V-RAPTOR [X], 3840×2160, 3494 frames at nominal 24000/1001, two R3D spans. First, middle, final and 3070/3071/3072 span-boundary frames were checked. Single-frame, sequence and relocated-copy PNG hashes match. The integrated worker registered both spans, approved an explicitly labeled fixture frame, copied/reopened/verified the package and undid it into retained recovery storage while preserving both source hashes and report bytes. The fixture labels exercise the workflow; no slate/OCR detection is implied. See [RED acceptance notes](REDLINE_ADAPTER.md).

The authorized Blackmagic RAW SDK 6.0 sample is genuine URSA Mini Pro 4.6K footage, 4608×2592 at 24 fps, with an attached sidecar. It contains **one frame**. The original local helper passes eleven native checks, including exact SDK index, full-resolution RGB, deterministic output, real sidecar pixel effects, malformed input, collision/symlink refusal, bounds and source preservation. Its framework version/build is 6.0/60000.40.271; the API's own `GetVersion` returns 0.0 and is retained separately. The integrated worker and native Swift bridge complete register/decode/approve/link/copy/reopen/undo using that clip and sidecar. Full-resolution helper PPM output is independently checked and converted into a 960-pixel-wide PNG review image by the network-disabled LGPL FFmpeg build with TIFF/PPM decoders. CPU previews honor the BRAW SDK defaults and attached sidecar; RED's explicit IPP2/BT.709 CPU review ignores external RMD look adjustments while preserving those sidecars in copies.

This does not establish BRAW temporal seeking, long-clip throughput, multicard BRAW, broader camera/firmware profiles, Windows native RAW decoding, physical camera connectivity, camera-card certification, slate/OCR detection, sensor-raw export, full real-time audio/timeline playback or named-NLE relink/conform support. Actual Windows native RAW tests require the corresponding authorized runtime and test machine. A Mac SDK containing Windows headers is insufficient.

## Tests and local builds

Normal tests use public synthetic MOV/MP4 and constructed package fixtures. Opt-in `RawIntegrationTests` read `SHOT_REPORTER_BRAW_SAMPLE`, `SHOT_REPORTER_BRAW_HELPER`, `SHOT_REPORTER_R3D_SAMPLE` and `SHOT_REPORTER_REDLINE`; both codecs also need local `SHOT_REPORTER_FFMPEG`/`SHOT_REPORTER_FFPROBE`. Real vendor fixtures are private and never checked into CI. Without those explicit paths, actual RAW tests are skipped with a reason; synthetic package tests are not evidence of RAW decoding.

`tools/build_desktop_media_dev.py` creates a fresh unsigned Mac development app/worker with a slim JRE and reviewed FFmpeg tools. It refuses an existing output directory and never replaces an installed app. The vendor decoder executable/framework is not copied into the app; configure authorized local tools separately. Keep the source archive, license files and matching source review for any future binary distribution. Store/TestFlight variants need their own signed packaging and sandbox/decoder validation before release. [Desktop updates](DESKTOP_UPDATES.md) remain disabled until trusted feed/key/publisher configuration and native upgrade tests are complete.

## Vendor license boundaries

The user authorized local Blackmagic SDK/bundled-sample use under its explicit Developer SDK agreement. Conditional vendor object-library redistribution is separate from Shot Reporter's MIT source license; do not publish the SDK, headers, dispatch source, examples, runtime, installer, footage or decoded sample images. The original adapter source merely references the separately supplied API; its local build compiles the vendor's original dispatch source from private storage. Production packaging needs a redistribution/third-party-technology review and corresponding vendor notices.

RED SDK 9.2.1 was inspected privately, but SDK-native integration is deferred: its header-information/sample redistribution limits and developer-program EULA conditions require review before a public SDK-facing implementation. Current public adapter code invokes the user's separately installed REDline CLI and redistributes no RED binary/SDK. The official SDK Broadcast footage remains internal validation material. No new web sample/SDK agreement was accepted by the agent and no further browser download is part of this workflow. No release, live update feed, signing identity, site change or TestFlight upload was created by this development work.
